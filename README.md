# SORA — личный VPN на собственном сервере

VPN (AmneziaWG) на вашем сервере, учёт трафика по людям, лимиты и
проверки, которые ловят и поломки, и обманы.

**Не замена Cloudflare WARP.** WARP у вас уже работает, бесплатно и
быстро. SORA даёт то, чего WARP не умеет: **свой адрес вместо
общего**, **учёт трафика по каждому** и **отзыв ключа**.

## Начать

```bash
cd SORA/tools

python sora_keys.py init                        # создать реестр
python sora_keys.py add ivan --note "ноутбук"   # выдать ключ
python sora_doctor.py                           # проверить
python sora_keys.py server --out ../server/server.conf
```

Последняя команда делает файл, который вы передаёте администратору.

## Проверка чужих ключей

Если вы скачали конфиги WARP и хотите понять, что с ними, есть два
инструмента. Подробности и все грабли — в
[docs/ПРОВЕРКА-КЛЮЧЕЙ.md](docs/ПРОВЕРКА-КЛЮЧЕЙ.md).

**Офлайн-анализ.** Не требует сети вообще — в коде нет ни одного
сетевого вызова, это проверяется. Разбирает папку, показывает
уникальные ключи, дубли, зоны, версии формата.

```bash
python tools/sora_keyscan.py C:/путь/к/конфигам
```

**Живой стенд.** Поднимает настоящий туннель в одноразовом
контейнере Docker и гасит его. Сеть вашей машины не затрагивается.

```bash
python tools/sora_warpcheck.py example.conf
python tools/sora_warpcheck.py --папка C:/конфиги --только-уникальные
```

Читать вердикт надо аккуратно: стенд отвечает на вопрос «**отвечает
ли сервер с этого адреса**», а не «работает ли ключ». Часть публичных
генераторов WARP выдаёт конфиги только на зарегистрированные адреса,
поэтому ключ, исправно работающий с телефона, из контейнера не
ответит.

## Ключевое отличие от WARP

| | WARP (бесплатно) | SORA |
|---|---|---|
| Цена | бесплатно | ваш сервер |
| Выход | ближайший узел Cloudflare | один адрес, Москва |
| Адрес | общий на миллионы людей | только ваш |
| Учёт по людям | **нет** | **есть, в байтах** |
| Отзыв ключа | нет | одна команда |
| Скорость | выше (сеть Cloudflare) | ниже (1 ядро, 768 МБ) |

**Держите оба.** WARP — для обычного сёрфинга. SORA — там, где нужен
свой адрес и важно, кто сколько качает.

## Учёт трафика и лимиты

На сервере месячный лимит 4000 ГБ. Учёт нужен, чтобы знать, сколько
осталось, и чтобы один человек не съедал весь объём.

```bash
sora_traffic.py limit ivan 100     # 100 ГБ в месяц
sora_traffic.py report             # кто сколько
sora_traffic.py status             # кто отключён
sora_traffic.py restore ivan       # вернуть
```

Превысивший **не удаляется** — отключается от туннеля. Обратимо.

Счёт идёт через счётчики `iptables`, а не через `wg show`. Это не
зависит от реализации VPN: метод одинаково работает и для
`amnezia-awg-go`, и для обычного WireGuard, и для любой замены.

## Три вещи, которые нужно знать про ключи

**1. Ключи создаются на вашем компьютере.** Не на чужом сайте, не
чужим сервисом. Приватная половина никуда не отправляется — она лежит
в `client\registry.json` на вашем диске.

**2. Приватные ключи не выводятся по умолчанию.** Чтобы увидеть —
надо явно попросить. Причина: он попадает в скриншоты и переписку.

**3. Потеря реестра = потеря доступа для всех.** Ключи не
восстанавливаются. Делайте `backup` и держите копию на носителе,
который не попадает в облако.

## Что было найдено и исправлено

Не скрываю, потому что это влияет на доверие к остальному:

1. **Bash не принимает кириллицу в именах переменных.** Проверено
   реальным запуском. Один скрипт просто не запустился бы.

2. **`bash -n` проверяет синтаксис, но не разрешение переменных.**
   Скрипт проходил проверку и при этом падал. Проверяется и то, и
   другое.

3. **Парсер ключей возвращал 0 человек.** Учёт тихо приписал бы
   трафик ничему — хуже, чем явная ошибка.

4. **Месяц зачитывался дважды.** Счётчики живут вместе со службой и
   при смене месяца не обнуляются. Объём у каждого удваивался бы.

5. **Возврат отключённого был перевёрнут.** Функция читала резервную
   копию и снова *вырезала* человека — то есть гарантированно не
   возвращала.

6. **Клиентская проверка называла утечкой адрес WARP.** Адрес
   Cloudflare идёт через туннель и утечкой не является.

7. **Две ложные тревоги в doctor.** Требовал зажима бит от
   PresharedKey (это не скаляр) и считал утечкой клиентский конфиг
   (он обязан содержать свой ключ).

8. **Тест на сломанных данных снёс реестр.** Откат был написан в
   обратную сторону. Тесты переведены на копию во временном каталоге.

9. **На вашем сервере отвечает любой TCP-порт** — включая заведомо
   свободный. Это антиddos-фильтр хостинг-провайдера. Первый зонд
   на это ругался бы «порт занят» при любом состоянии сервера.

10. **Конфиг, подложенный в stdin, не доходит до устройства.**
    `amneziawg-go` принимает его, но не применяет. Туннель
    поднимается пустым. Хуже всего, что это **выглядит как
    работающий туннель**: счётчик исходящих байтов растёт, его
    пишет ядро в TUN независимо от того, читает ли пакеты кто-нибудь.
    Снаружи неотличимо от «ключ отправил, сервер молчит». Настоящее
    решение — `awg setconf` через UAPI после запуска процесса.

11. **Успешный `ping` не доказывает, что туннель работал.** Если
    маршрут по умолчанию не переключился, трафик идёт обычной
    дорогой контейнера и даёт 0% потерь. Первый «успешный» прогон
    стенда был именно таким — пинг ходил мимо туннеля.

12. **Проверка живости в конвейере врёт.** В конструкции
    `( sleep 600 ) | amneziawg-go &` переменная `$!` указывает не
    на процесс `amneziawg-go`, и `kill -0` объявляет живой процесс
    мёртвым. Живость проверяется через `pidof` или ответ UAPI-сокета.

13. **Строка `peer:` в выводе `awg show` начинается в колонке 0**,
    тогда как остальные поля интерфейса сдвинуты на два пробела.
    Проверка по шаблону `^  peer:` не срабатывает никогда.

14. **Отбор «по ключу» шёл по серверному ключу.** Поле `PublicKey`
    в секции `[Peer]` принадлежит серверу, и у всех конфигов одного
    генератора оно одинаковое. 126 файлов схлопнулись в один
    ключ, и 28 остались непроверенными без единого предупреждения.
    Личность ключевой пары задаёт приватный ключ.

Все четырнадцать ошибок описаны подробно в
[docs/ПРОВЕРКА-КЛЮЧЕЙ.md](docs/ПРОВЕРКА-КЛЮЧЕЙ.md) — вместе с
командами, которыми каждая из них была найдена.

## Чего здесь нет намеренно

**Ротации IP для обхода лимитов сторонних сервисов.** Нарушение
условий чужих сервисов и почти гарантированный бан существующих
аккаунтов. Снято 15.10.2026, зафиксировано в ТЗ.

**Docker на сервере.** При 768 МБ памяти он забирает 400–500 МБ
только на себя — на сервере с тремя пользователями это
недопустимо. Поэтому стенд проверки ключей запускается на **вашем
компьютере**, а не на сервере: туннель живёт 10–35 секунд внутри
контейнера и гаснет вместе с ним. Сервер SORA Docker не нужен.

## Опубликованная копия не содержит ваших ключей

Этот репозиторий — публичный, без единого вашего ключа и без
рабочего адреса сервера. Проверяется автоматически:

```bash
python tools/build_publish.py
```

Сборщик создаёт отдельную копию пакета, в которой:

- **настоящие ключи заменены свежими** (`alice` и `bob`) — они
  настоящие по форме и проходят все проверки, но не соответствуют
  ни одному существующему серверу;
- **адрес сервера заменён** на `203.0.113.10` из RFC 5737 —
  подсеть, зарезервированную специально для документации;
- **личные документы владельца удалены**;
- файл `secrets.local.json` в публичной копии **не существует
  вообще**, даже пустой.

Затем сборка проверяется сканером: ищутся не «похожие на ключ»
строки, а **точные значения** ваших настоящих ключей. Совпадений
нет — значит ключей нет. Дополнительно проверяется, что рабочий
адрес не остался ни в одном файле, включая бинарники.

Тот же сканер можно прогнать по любой сборке отдельно:

```bash
python tools/publish_check.py client/registry.json путь/к/сборке
```

## Как это сделано безопасно

**Ключи не попадают в git.** `client/` и `server/server.conf` в
`.gitignore`. Попадание ключа в историю необратимо: его придётся
заменить, а отозванные старые конфиги останутся в чужих клонах.

**Перед публикацией код проходит проверку.** `find_cyrillic.py`
ловит то, что не видит компилятор: кириллицу в именах переменных
bash, смешанные алфавиты в словах, BOM, CRLF вместо LF, табы.
Каждая находка этого скрипта была настоящей ошибкой — включая
две в моём собственном коде, найденные с первого прогона.

**Тесты идут на копии.** Ни один тест не трогает настоящий реестр:
фикстуры всегда создаются заново во временном каталоге. Раньше
тест копировал реальный реестр с приватными ключами и падал на
`KeyError` — теперь не копирует.
